# 漫画来源标签

漫画详情的「添加标签」用于人工编辑。「补充来源标签」接受来源网页、每行一个的原始标签和匹配说明；提交后进入「数据管理 → 人工复核 → 漫画来源标签」，通过后才写入标签。

浏览器采集时保留命名空间，例如 `female:glasses`。当前入口保留原词，不自动翻译、合并作者身份或判断不同版本相同。已有人工标签不会被来源候选覆盖。

## 使用 Ego 批量采集

1. 在电脑的 Ego 中打开部署在 NAS 上的 Pear，进入漫画详情；另一页打开来源网站。
2. 核对标题、作者、语言、页数和版本。存在歧义时不要提交给猜测的资产；匹配说明保留判断依据。
3. 将来源 URL 和原始标签整组填入「补充来源标签」，提交后记录回执。相同资产、URL 和标签集合的重复提交只保留一份候选。
4. 使用「下一本待补标签」继续。页面刷新后，待补清单排除已有来源候选的漫画。补充第二个来源时直接打开该漫画详情再次提交。
5. 由用户在复核页检查来源与本地漫画，再通过、忽略或稍后处理。采集 AI 不操作「通过」。

验证码需要人工处理；访问失败应记录在采集任务中，不能填成「没有标签」。当前实现提供提交与复核入口，不包含无人值守的 Ego 调度、失败任务持久化或跨实例同步。

## 接口

- `GET /api/comic-tag-queue?after=0`：按资产 ID 返回至多 50 本未提交候选的漫画，包含名称、页数、来源位置、可取得的媒体库身份、详情与封面 URL；使用 `next_after` 继续分页。
- `POST /api/comic-source-tags`：请求含 `id`、`source_url`、字符串数组 `tags`、可选 `evidence`；响应含稳定 `item_key`。沿用应用认证及写入权限，不从来源网页跨域调用。
- 复核沿用 `/api/review` 和 `/api/review/decision`，类别为 `comic_source_tags`。

候选保存于当前实例生成目录的 `comic-source-tags-candidate-browser.csv`。批准后的关系保留来源 URL、原始标签和复核项标识。NAS 容器需持久化整个应用数据目录；AI 所在电脑只需能够访问该实例，无需挂载漫画目录或将 Ego 安装到 NAS。
