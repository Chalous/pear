# 漫画来源标签

漫画封面的「编辑标签」打开当前漫画的标签弹窗，可直接添加、移除并撤销最近一次操作；列表中入口位于「稍后看」旁，详情封面也有入口。普通浏览模式即可操作，无需 `?edit`（该参数用于修改界面文案）。详情侧栏的「添加标签」也可用于人工编辑。「补充来源标签」接受来源网页、每行一个的原始标签和匹配说明；提交后进入「数据管理 → 人工复核 → 漫画来源标签」，通过后才写入标签。

浏览器采集时保留命名空间，例如 `female:glasses`。当前入口保留原词，不自动翻译、合并作者身份或判断不同版本相同。已有人工标签不会被来源候选覆盖。

优先搜索 WNACG：先用完整漫画名，未找到时移除末尾方括号附加信息重试，仍未找到则记录「未找到」。中文标签优先，繁简转换时在匹配说明保留来源原词。作者填写独立的「作者」字段，不只混入内容标签；该字段也需要人工复核。只有作者、没有新标签时也可提交。既有作者不同时拒绝直接覆盖，需核对资料。审核通过后的标签进入首页筛选，作者进入左侧「作者」索引。

## 使用 Ego 批量采集

1. 在电脑的 Ego 中打开部署在 NAS 上的 Pear，进入漫画详情；另一页打开来源网站。
2. 核对标题、作者、语言、页数和版本。存在歧义时不要提交给猜测的资产；匹配说明保留判断依据。
3. 将来源 URL 和原始标签整组填入「补充来源标签」，提交后记录回执。相同资产、URL 和标签集合的重复提交只保留一份候选。
4. 使用「下一本待补标签」继续。页面刷新后，待补清单排除已有来源候选的漫画。补充第二个来源时直接打开该漫画详情再次提交。
5. 由用户在复核页检查来源与本地漫画，再通过、忽略或稍后处理。采集 AI 不操作「通过」。

验证码需要人工处理；访问失败应记录在采集任务中，不能填成「没有标签」。当前实现提供提交与复核入口，不包含无人值守的 Ego 调度、失败任务持久化或跨实例同步。

## 接口

- `GET /api/comic-tag-queue?after=0`：按资产 ID 返回至多 50 本未提交候选的漫画，包含名称、页数、来源位置、可取得的媒体库身份、详情与封面 URL；使用 `next_after` 继续分页。
- `POST /api/comic-source-tags`：请求含 `id`、`source_url`、字符串数组 `tags`、可选 `creator` 和 `evidence`；响应含稳定 `item_key`。沿用应用认证及写入权限，不从来源网页跨域调用。
- 复核沿用 `/api/review` 和 `/api/review/decision`，类别为 `comic_source_tags`。

候选保存于当前实例生成目录的 `comic-source-tags-candidate-browser.csv`。批准后的关系保留来源 URL、原始标签和复核项标识。NAS 容器需持久化整个应用数据目录；AI 所在电脑只需能够访问该实例，无需挂载漫画目录或将 Ego 安装到 NAS。

## 重复批处理与成本

稳定的接口、复核语义和部署说明保留在本文；反复执行的浏览器操作适合封装为个人 skill，引用本文而不复制接口契约。skill 负责选择实例、匹配作品、暂停交接及提交候选；确定性的标题清理、限流、断点和回执记录交给配套脚本。

断点应绑定实例地址、媒体库身份、资产 ID 和来源 URL。重扫后的 ID 可能变化，恢复时必须核对标题和页数，不能仅按旧 ID 写入。逐项区分已提交、未找到、访问失败和待人工判断；网页访问失败不能当作未找到。每完成一本即保存回执，恢复后不重复搜索已完成项。

成本记录区分网站请求次数、有效运行时间、模型输入输出与账单用量。网页提取只返回标题、页数、标签及必要证据，避免每本输出整页快照。没有供应商用量回执时只能报告文本估算，不能把字符数当作精确 token 或计费金额。
